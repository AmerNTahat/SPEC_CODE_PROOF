# Goal 10 — Test, package and finish the actual application
## Test layers
Unit tests for schemas, budgets, states, hashing, approval logic, lexical comparisons, invalidation and retrieval filters. Adapter conformance tests against recorded supported events; real installed CLI smoke tests. Parsed architecture mutation tests. Toolchain integration on selected examples. Browser/CLI parity tests. Isolation and attestation tamper tests. Fresh-session transfer experiments with explicit paid-run authorization.

## Required failure coverage
Missing tools/model/auth; wrong source role; leaked source solution; malformed agent output; wrong operation ID; exhausted limit; repeated no-progress repair; hung process; missing contract; wrong owner; role-swapped connection; invalid timing; vacuous assumption; hidden bypass; zero valid tests; stale evidence; altered signature/hash; unknown signer; unsupported mandatory check; UI reload during approval; interrupted publication.

## Release artifacts
Source and dependency locks; idempotent environment setup/recovery; project examples/configuration; CLI help and UI user guide; source provenance/license inventory; models/tool capabilities; source/requirement/architecture/evidence schemas; reproducible demos; traceability; independent attestation verifier; experiment protocol/results; limits and actual blockers.

## Acceptance demonstration
From either interface: choose learning data -> bounded learning -> review/publish -> new task with frozen rules -> controlled repair -> full required checks -> inspect traceability -> independently verify evidence -> compare with a non-evolving baseline. Demonstrate default automatic and interactive assistance.

## Honest status
Package checksum/unit tests and mocked UI events do not establish Sireum/HAMR integration. Do not mark milestones complete from stubs or synthetic passes. Do not invent repository revisions, model availability, published digests, costs or proof results. Record what was run and what was not. CI does not spend model tokens without recorded authorization.

Implement incrementally and leave resumable progress; do not stop at another proposal. No unauthorized remote push, publication, model substitution, or destructive installation. Preserve original DASC artifacts.

## Integrated v2.0 blockers
Release tests must cover goal installation with changed working files; source rulebook import/conflicts; manual/automatic split approval and lineage; UI/CLI config/budget parity; existing-code completion/proof repair without unwanted reconstruction; explicit blank-project creation; consistent renaming and broken-role rejection; full-stack repair retrieval with negative near-match; verified-unit counting and stale evidence; signed evidence tampering; actual live demo. The package's support tests cannot close these app milestones. Emit progress after every milestone and a truthful final BUILD_RESULT manifest.
