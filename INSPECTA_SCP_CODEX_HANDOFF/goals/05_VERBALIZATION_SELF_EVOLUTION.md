## Full-stack knowledge

Use one authoritative rule record with combined/specialized views and dependency/conflict links. Separate abstract rule, task binding, repair episode and deterministic executable procedure. Do not embed all books in every call. Restrict procedures to reviewed code/registry entries, never arbitrary commands mined from documents.

## Structured verbalization

Ask what activates the pattern, what relationship expresses the intent, where it belongs, and what gate detects a wrong application. Add source-versus-inference distinction, typed substitutions, positive paraphrases, misleading near-matches, alternatives rejected for stated reasons, unsupported scope and a counterexample. No hidden-chain-of-thought requirement; concise engineering rationale and observable evidence only. Store model confidence as a forecast, not empirical success probability.

## Feedback and repair reuse

Normalize diagnostics while retaining raw evidence. Separate failure location from hypothesized cause. Filter tool/version/profile/operation first, then use local lexical and structural retrieval; Astra selects only when ambiguous. Similar text alone cannot authorize the same repair. Bind the rule to current roles and test an isolated patch. Record failed transfers. In User Mode queue lessons; do not change the frozen release.

## Learning and meta-learning

Extract -> forecast -> instantiate -> tools -> diagnose -> generalize/specialize/split/merge/retire -> development transfer and regressions -> approval -> publication. Support/query development episodes may tune extraction/retrieval policies; final evaluation stays untouched. Keep extraction, example retrieval, refinement and preference-ranking effects separately measurable. Optional preference experiments remain off initially and no Jev or fine-tuning is required.
