# Required live demonstration after implementation

Status:
This is an executable-workflow requirement for Codex to implement and run on the authorized workstation. No live HAMR/Astra demo is pre-recorded in this handoff.

## Authorization and scope

Before paid execution, review one bounded campaign configuration: allowed public/project sources, model/profile, task registry, total time/tokens/spend, per-run ceilings, repair scope, and approvals. Default configuration is not authorization. Count extraction/repair/confidence/retries in the parent budget. Do not solve insufficient budget by skipping required gates. Actual production materials require their own permission.

## Sequence

1. Run doctor, validate the locked environment and instantiate an approved Isolette reproduction/development split. Audit both tool manuals and embedded worked answers. Register real target units; do not invent 42 entries.
2. Import the existing rulebook library as a source release and review its current compatibility. Run a small actual learning cycle that extracts or refines a meaningful full-stack pattern from authorized materials/feedback. Show original model forecast and observed evidence.
3. Test a discriminating development case and counterexample, inspect generalization/specialization, then obtain publication approval for a demo release.
4. Start a fresh User session using that frozen release on a declared continuation/completion task. Preserve existing artifacts, names and architecture. Inject a deliberate incorrect connection or ownership change in an isolated test candidate and show rejection without corrupting the approved project.
5. Run the selected target's actual generation, code/proof/test/build gates. Missing/timeout/unknown is not pass. Report accepted/verified/end-to-end separately.
6. Execute at least one selected KSU Producer/Consumer or Network Guard workflow using its correct profile and actual GumboX/proof tests. Clearly separate it from independent held-out transfer if it was used in learning.
7. Separately exercise the optional create-system capability with explicit task authorization. No completed target model may be supplied as a seed; common libraries are allowed. Test global consistent internal renaming and reject a same-typed role swap. Record underspecified architecture as conformance/design review, not forced equivalence.
8. Export DASC-style metrics, raw normalized records, plot files, provenance and a traceability walkthrough. Compare against a matched static workflow only when the corresponding actual baseline exists.
9. Create and independently verify the evidence bundle; deliberately tamper with a copy and show rejection. Capture a replay from the actual run. Recordings must identify their source run and not masquerade as live execution.
10. Guide the user to open the real UI, resume a permitted cycle, change budget/split settings through the shared resolver, and run validation without editing sources.

Outcome, scope, achieved, in progress, remaining, blockers, operation classes, actual commands, run IDs, tool/model/library versions, token/time/cost accounting, unit definitions and outstanding approvals.

Actual raw logs, manifests, artifact hashes, traceability, validation, and integrity verification. No credentials or unrestricted evaluator data.

Real normalized data plus plots, all labeled live/historical/synthetic accurately.

reports/demo/replay/:
Recorded application events and browser assets referencing the real run. A static design mockup remains separately labeled.
