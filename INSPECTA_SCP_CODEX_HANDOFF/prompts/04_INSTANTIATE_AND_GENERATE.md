# Apply frozen patterns to the requested task

Inputs:
Resolved run configuration, operation and edit scope, approved requirement ledger, active existing files (where supplied), protected architecture and names, selected rules/dependencies, current toolchain syntax references, and remaining budget.

Before generation:
Bind each abstract rule role to current source requirements and resolved model/code entities. Distinguish required and inferred architecture; report ambiguous design choices. Preserve existing correct work and uncommitted edits. Creation requires explicit authorization and an empty separate target workspace; common libraries are allowed but target solutions are not.

Generate:
For continuation/completion/repair, produce the smallest justified changes in authorized files/regions. For explicitly requested whole-system creation, generate connected packages/types/components/ports/connections/properties and complete applicable GUMBO behavior, then requested code/proof support. A recommendation or fragment is not a complete system. No invented unsupported syntax. Use current profile examples; keep generator-owned files under regeneration procedures.

Output:
Patch/artifacts, exact rule bindings, source trace links, requirement coverage claims to check, unresolved decisions, and required tool actions. The controller executes checks and decides acceptance. Do not overwrite raw references, remove obligations, change library releases, or treat textual similarity as structural/behavioral correctness.
