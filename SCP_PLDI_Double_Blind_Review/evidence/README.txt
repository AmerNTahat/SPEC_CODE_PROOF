Supporting records and figure data

The JSON files are anonymized extracts from read-only audits. sng-learning-records.json contains the selected context counts, all eleven matched lesson records, and common-guide comparisons. evidence-audit.json contains the file and receipt comparisons, saved pilot assertions, and F01/control record summaries. timing-model-audit.json adds the recovered timing intervals, historical attribution, selected configuration fields from 117 call receipts, and source hashes. support-session-usage.json gives selected usage snapshots and totals for three supporting Codex sessions, with counter consistency checks.

coverage-method-audit.json traces one SNG requirement through its named contract, proof evidence, premises, and review. It records the relevant service-source hashes, the case-specific requirement mappings, and the optional generic mapping fields that were unset in the inspected model runs. comparison-plot-data.json supplies the measured token bars, cumulative milestones, later repair facts, and six category results used by figures/plot-comparison.py. figure-sources.json records hashes for the cited presentation material and primary literature links used for the original diagram adaptations. The schematic search-tree counts and applicability curve are illustrative.

accounting-and-release.json reconciles the 117 experiment-worker calls through the 6 November SNG closeout, separates nested task checkpoints from disjoint case histories, and records the applicable budget scopes. A separately dated observation identifies the later BASS calls excluded from this paper's cutoff. The extract also preserves review timestamps, the inspected generic-coverage configuration, and the three owner release decisions recorded on 8 November under reviewer POWERUSERS-1. Each release identifies its candidate, scope, premises, remaining technical obligations, and primary receipt hash. Original historical review and technical statuses retain their dates. The 28M allowance covers the experiment-worker ledger; selected supporting-session usage is reported separately.

cost-normalization.json records the model-stage ceilings and observed completions, the GPT-6 Astra rate-card calculation, and the SNG model-token cost per delivered source line. Standard rates apply separately to uncached input, cached input, and output. The support example uses cumulative counters and illustrates two rate scenarios. A separate allocation illustrates the cost of charging both later worker arms and the three supporting counters to the one delivered SNG build.

claim-check-index.json links selected manuscript claims to their source lines, supporting extract fields, and primary literature.

revision-link-audit.json records the cross-check of the Gate and Filter proof-input fingerprints against the SNG build and QEMU inventories. It also records the application checkpoint test rerun and the selected fixture tests for evidence freshness and signed export. The proof-input cross-check uses the saved extracts. The application tests use synthetic fixtures.

source-line-counts.json transcribes the summary of the authors' 8 November local source audit. It separates the successful builds from the additional Scala inventories and gives the counted languages and scope. The detailed per-file counts and fingerprints are in the local audit. source-role-counts.json records the follow-up aggregate counts in Appendix A, including the associated retained Isolette model and the split by file purpose.

workbench-python-inventory.json transcribes the authors' 9 November Workbench snapshot summary, including implementation, automated tests, and validation and support scripts. The summary reports agreement between two methods and provides category totals. The counted revision and method details can be recorded with a reproducible inventory of that snapshot.

Absolute local paths are replaced with anonymous record identifiers. A records/ identifier names an original record; it does not imply that the original file is present in this package. Original source-file hashes and numerical outcomes are preserved. The source_audit_sha256 fields identify the unmodified source audits. The SNG extract includes the original lesson observations and review states, but omits superseded prose interpretations from the audit. Supporting-session prefix hashes identify the bytes through the stated cutoff; raw messages and account information are excluded. One final cumulative counter per session is used. Cached input is part of total input, and reasoning output is part of total output.

These records support inspection of the reported counts and consistency checks. Repeating the engineering executions requires the full implementation, run inputs, and tool environments, which are not included in this manuscript source package. No new engineering experiment was run to prepare these extracts.
